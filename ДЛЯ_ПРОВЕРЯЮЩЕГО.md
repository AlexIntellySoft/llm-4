# Карта для проверяющего

Короткая навигация: что требовалось по заданию → что сделано → где смотреть →
как проверить самому.

Основной артефакт — [`notebooks/rag_report.ipynb`](notebooks/rag_report.ipynb),
все выводы ячеек сохранены, запускать не нужно.

---

## Шаг 1. Развёртывание локальной LLM и подготовка окружения

| Требовалось | Сделано | Где смотреть |
| --- | --- | --- |
| Выбрать и скачать открытую модель | Три модели: `qwen3-4b-2507` (основная), `gemma-4-e4b`, `qwen3.5-9b` | `src/config.py`, блок `LLM_MODELS` |
| Развернуть локально | LM Studio, OpenAI-совместимый сервер на `127.0.0.1:1234` | `src/llm.py` |
| Убедиться, что модель отвечает и работает без интернета | Проверено с `HF_HUB_OFFLINE=1`; единственный сетевой адрес пайплайна — `127.0.0.1` | ноутбук, раздел 0 |

Внешние платные API не используются нигде: в коде нет ни одного обращения к OpenAI
или Яндекс.Облаку, `base_url` всегда локальный.

Сверх задания проверено:

* **порог близости не отделяет вопросы вне базы** — диапазоны пересекаются (4.2);
* **сравнение эмбеддеров** — Recall@k на русском корпусе (4.4);
* **строгий промпт против наивного** — что он реально даёт (4.5);
* **indirect prompt injection через документ базы** — сработала в 3 прогонах из 4 (4.6);
* **отсутствие разграничения доступа** — SECRET-документ выдаётся любому (4.7);
* **цена «рассуждения» у thinking-моделей** — задержка и пустые ответы (4.9).

## Как проверить самому

Полный прогон с нуля (нужен LM Studio и одна модель):

```bash
lms get qwen/qwen3-4b-2507 && lms server start

python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

python -m src.ingest                    # индексация, ~2 с на 59 чанков
python -m src.rag "Какие суточные при командировке по России?"
python app.py                           # http://127.0.0.1:7860
```

Повторить измерения:

```bash
python -m src.experiments main          # 20 вопросов, ~2 мин
python -m src.experiments all           # все восемь экспериментов, ~40 мин
```

Результаты каждого прогона складываются в `outputs/*.json`, ноутбук собирается из них:

```bash
python tools/build_notebook.py
jupyter nbconvert --to notebook --execute --inplace notebooks/rag_report.ipynb
```

## Что стоит знать при проверке

1. **Корпус вымышлен целиком.** АО «Полярис Технологии», его регламенты, суммы и
   адреса придуманы. Часть фактов намеренно расходится с законодательством
   (отпуск 31 день, суточные 2 500 ₽, испытательный срок 2 месяца) — иначе тест
   на конфликт фактов ничего не проверяет.
2. **Файл `data/raw_optional/10_injection_probe.pdf` содержит учебную
   prompt-инъекцию.** Он лежит отдельно и в основной индекс не попадает —
   подключается только в эксперименте 4.6.
3. **SECRET-документ с окладами выдаётся любому пользователю, и это сделано
   намеренно.** Фильтр по правам доступа не добавлен, потому что он скрыл бы
   главный вывод работы о надёжности. Как именно его добавить — описано в 4.7.
4. **Грейдер проверяет ответы по подстрокам с учётом падежей.** Первая версия
   сравнивала буквально и забраковала один верный ответ; это разобрано
   в ноутбуке (оговорка после 4.8), оригинальные вердикты сохранены
   в `outputs/pre_regrade/`.
